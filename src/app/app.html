Simple GitHub Story

Accessibility is important when writing code and providing pull requests. Therefore this application exists to implement a ticket in 2 different stories:

  1. I have no clue what accessibility is when using git.
  2. I do have a clue what accessibility is when using git.

This is the use case that will be handled to showcase it. It's obviously held generically and small scoped to easily understand it. What's out of scope? What's out of scope? I will elaborate on git topics only. Coding itself and what is considered good code it not part of this presentation.
